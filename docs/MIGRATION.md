# 兼容与迁移决定

## 保留与改变

- 聊天：采用已发布流式编码基线；原工作区的逐条 PCM→M4A→MP4 实验改动保留在原处及维护者只读差异证据。它增加编码轮次，不是已证明必须替代流式核心的修复，本版不盲目合并。
- 公众号：纳入业务工作区的总暂停/继续、定时周期记录、同任务恢复、原生会话恢复、短内容解析、去重索引和对应 UI/状态栏代码。没有迁移真实数据库。
- 课程：把本机绑定脚本转换成清单适配器，复用回放 ASR/Word 核心。特定平台的登录/API 获取、私有版本映射、专名替换和历史质量记录保留为原项目能力，明确不纳入自动通用入口。
- 媒体：复用维护仓库作为转录的依赖；保留提供商识别、获取、下载、转换和校验。旧可选 token/第三方脚本需独立授权，统一入口不自动使用。
- 自动删除：公众号统一入口将自动 prune 限定为预览。真正删除需按用户规则另行审阅，不沿用旧组件的自动清理行为。

## 数据位置

套件环境和媒体/公众号/课程/回放任务使用当前用户的 `WeChatAIServices` 应用支持目录。
聊天账号私有状态使用 `WeChatAIServicesChat`，不会自动复用原 `WeChatLocalExport`。
组件原始直接命令还保留自己的命令形式；普通使用必须走根路由，避免落到默认旧路径。

现有账号迁移没有自动执行：先备份、确认新旧 schema、哈希、账号与权限，再在新目录验证；不能把一个账号的快照套给另一个账号。新建空库不代表完成历史迁移。

## 后台服务

统一安装不注册任何 LaunchAgent。公众号 CLI、本地控制台、原调度/状态栏源码均保留。
根路由拒绝后台安装/卸载，避免用户一次普通使用就开始定时操作微信。
确需独立后台部署时，先审阅 `components/articles/wechat_crawler/launch_agent.py`：套件名称使用 `com.local.wechat-ai-services-articles`，应用名称/端口均与旧版区分。应在独立套件运行目录创建 `.venv` 和配置，核对旧服务身份仍保留，再执行显式安装。
本版没有启动后台服务，也没有验证新状态栏的真实通知/权限流程；不把 Swift 编译当成后台验收。

## 回滚

源码是新仓库和独立 checkout，原项目未修改。停止本套件自己启动的进程可回到原工作流；本轮未启动后台服务或修改系统代理。
不要为了回滚删除账号状态或输出。依赖环境、证据和输出保留，清理另行列清单审批。
