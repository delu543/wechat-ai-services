# 课程合集：从显式清单到完整 Word

输入是用户有权保存的本地音视频。远程链接先通过 media 能力取得并验证，再填入路径。
不从本机历史任务猜测课程清单，不自动读取课程网站凭据或付费接口。

私有 JSON 清单示例（路径相对清单文件解析）：

```json
{
  "schema": 1,
  "collections": [{
    "id": "collection-1",
    "title": "课程合集",
    "lessons": [{
      "id": "lesson-1",
      "title": "第一课",
      "sources": [{"kind": "audio", "path": "media/lesson-1.m4a"}],
      "source_text": ["用户有权提供的讲义原文，可省略此字段。"]
    }]
  }]
}
```

每合集与每课 ID 唯一；数组顺序就是文档顺序。存在一个 audio 时优先使用，只有没有 audio 才选择一个 video；多个同类型候选停下，不猜版本。

```text
python3 wechat_ai.py run courses -- plan <私有清单>
python3 wechat_ai.py run courses -- run <私有清单> --model <本地MLX模型目录>
```

先冻结媒体哈希与模型哈希。单 ASR worker，每 15 分钟保存配置/音频绑定的检查点，词时间戳处理重叠。保存完整原始机器转写，标记低置信度，不自动按特定讲师名单替换人名。
已完成的转写按哈希复用；失败不自动循环。修复明确原因后可用 `--retry-failed`，总计最多两次 ASR 尝试。源文件变更会产生新的冻结任务，旧证据保留。

仅全部课完成的合集才生成 Word，逐段比对转写正文并保留讲义原文。输出报告 `body_verified_render_review_pending`：仍需渲染并逐页检查，不能称最终排版验收完成。
独立合集可以先交付，但必须报告哪些合集仍未完成。

原课程平台的数据层登录/API 抓取与特定账号音频映射没有通用的公开接入合同，保留在原项目，不自动迁移其凭据或状态。本适配器覆盖通用层级、选择、ASR、恢复、讲义和文档逻辑，不宣称支持任意付费课程网站。
