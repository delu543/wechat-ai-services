# 微信数据提取项目

## 新增：视频号直播回放 → 完整 Word

提供独立的 [wechat-replay-word Skill](portable_skill/skills/wechat-replay-word/SKILL.md)：
从一条种子链接绑定账号，自动分页收集可访问回放，提取音轨、本地离线转写、按场生成带时间戳的完整 Word，
并提供每5秒更新的只读本地进度面板。聊天导出能力保持原样，直播不需要聊天数据库初始化。

新电脑的第一句话、依赖安装、一次播放绑定、临时接入审批、网络回滚和验收步骤，见
[直播文字稿运行手册](portable_skill/skills/wechat-replay-word/references/workflow.md)。
当前是 **Apple Silicon macOS 源码预览**；通用封装和新电脑完整链路仍需各自验收，
不保证任意微信版本或所有电脑开箱即用。Windows 聊天导出预览不等于 Windows 直播支持。
目录已收齐不等于全部 Word 已生成；不会将中间进度或部分成功包装成全量完成。

```bash
npx -y skills add delu543/wechat-data-extraction --skill wechat-replay-word
```

只读打开仓库不会执行代码；运行时下载、模型下载、临时证书/网络变更仍按具体请求与权限处理。
没有 Cookie 上传或远程转写。Word 是最终成品，中间媒体不会未经确认自动删除。

通过 Codex 对话，在本机按“聊天名称 + 时间范围 + 内容类型”导出本机微信 4.x 数据。Mac 保留现有能力，新增 Windows 10/11 x64 源码预览。
支持文字、图片、语音、普通文件和部分可验证表情；语音可直接按顺序合并成 MP4。

> 当前版本：`0.2.0-dev.9` 开发预览。它是完整源码与 Codex Skill，不是已经签名、公证的
> 消费级 App。仅限处理本人有权访问的本机数据。Windows 尚无官方微信实机验收记录，
> 不能保证所有 4.x 构建可用；详见 [Windows 说明与验证边界](docs/WINDOWS_SUPPORT.md)。

## 最简单的使用方式

### Windows 用户：先复制这段给 Codex

在 Windows 电脑的 **Codex 本地任务**中发送（不是在微信里发送）：

```text
我用 Windows 10/11，请帮我在本机安装并使用这个项目：
https://github.com/delu543/wechat-data-extraction
请取得完整源码，读取 AGENTS.md 和 docs/WINDOWS_FIRST_RUN.md，按 Windows 新手流程检查和安装。
需要我本人登录微信或确认隐私操作时，一次明确告诉我下一步；其余能安全代办的步骤由你完成。
如果本地已有这个项目，先检查，不要覆盖已有文件或改动其他项目。
```

**安装时可以先不登录微信；初始化和日常导出时必须登录并保持微信打开。** 已经登录就
不必退出重登，打开任意聊天即可；不需要截图、寻找数据库、翻到历史位置或逐条播放语音。

用户本人需要：按提示完成微信登录/手机确认；首次发送 `$wechat-local-export-setup`；
分别确认“本次初始化”和“私有解密快照保留”；告诉 Codex 群名、时间和内容类型。
缺少 Python/VC++、系统权限或 Skill 未加载时，Codex 才会提示额外的安装确认/重启操作。
普通归档扫描后确认数量；明确要求纯语音直接 MP4 且检查通过时可省去该次导出确认。

完整步骤和 Codex 每一步应怎么回复，见 **[Windows 新手指南](docs/WINDOWS_FIRST_RUN.md)**。
Windows 仍是源码预览，尚未完成真实微信账号实机验收；不能承诺所有 4.x 构建均可用。

### 1. 在 Codex 中打开这个仓库

仓库地址：

```text
https://github.com/delu543/wechat-data-extraction
```

打开仓库后对 Codex 说：

```text
帮我安装并检查“微信数据提取项目”。
```

Codex 会读取根目录的 `AGENTS.md`，先运行只读检查，再调用幂等安装器。安装器会：

- 把完整源码复制到当前用户的私有应用支持目录；
- 安装固定版本、固定哈希的普通运行依赖；
- Mac 构建 Swift 辅助程序；Windows 安装原生解码依赖和 FFmpeg，无需 Swift；
- 安装 `wechat-local-export` 和 `wechat-local-export-setup` 两个 Skill；
- 不自动提权，不进入微信密钥初始化，也不读取聊天内容。

出于安全原因，仅仅打开 GitHub 链接不会静默执行代码。用户发出“安装”或“使用”请求后，
Codex 才会开始安装。依赖下载、macOS 权限和首次账号初始化仍保留明确的用户边界。

### 2. 第一次使用某个微信账号

登录官方微信并打开任意聊天，然后显式对 Codex 说：

```text
$wechat-local-export-setup
```

setup 会先做只读诊断。以下动作彼此独立，必须分别获得明确同意：

1. 仅在缺少时安装初始化依赖；Windows 复用普通安装的依赖，不再安装 Mac 的 Frida；
2. 初始化当前账号所需的精确数据库密钥：Mac 使用原有受控流程；Windows 保持微信打开，只读观察同一用户的当前进程；
3. 创建并保留该账号的本机私有解密快照。

普通安装不会自动进入以上流程。每个新微信账号都需要单独初始化一次。
历史账号目录不会显示为可选项；程序只接受当前官方微信进程能够唯一证明的账号绑定，
不会按文件时间、目录顺序或大小猜测账号。

### 3. 日常直接对话

账号初始化完成后，微信通常保持打开即可：

```text
把“示例讨论群”2026 年 7 月 24 日 14:00 到 15:30 的所有语音直接合成 MP4。
```

```text
先扫描“项目讨论群”昨天 9:00 到 18:00 的文字、图片和文件，告诉我各有多少条。
```

```text
归档“家人群”本周一到周三的文字、图片、语音和文件。
```

Codex 会换算绝对时间、精确匹配聊天、在线生成安全快照并验证结果。群名有歧义、账号绑定
不唯一、媒体缺失或数据库状态不受支持时会停止，不会猜测。

## 截图、首次使用和数据范围

**截图不是数据采集入口，也不是必需条件。** 它最多用于帮助用户说明目标聊天和起始时间；
正式定位由当前账号、数据库中的准确聊天名/ID、绝对时间范围和内容类型完成。没有截图时，
直接告诉 Codex 群名、时间和要导出的类型即可；扫描会先返回匹配结果、条数和首末时间，
有歧义时停止等待用户确认。

首次使用不以“有没有手机”作为判断，而看以下两个条件：

- 官方微信已经登录，并且当前账号已通过显式 `$wechat-local-export-setup` 完成一次本地初始化；
- 请求的消息和媒体已经保存在这台电脑的本地数据中。

如果官方微信要求手机或二维码完成登录，本工具不会绕过该流程。新电脑上尚未同步、下载，
或已经不在本机的数据和附件，也不能由本工具恢复。

后端不能被描述为“捕捉全部微信信息”。准确范围是：在指定当前账号、聊天和时间段内，
扫描后端支持且本机实际存在的数据。支持类型见下表；视频本体、未下载附件，以及未知或
不支持类型的完整内容不属于完整导出承诺。对应记录会保留可用元数据或明确状态；严格模式
遇到缺失、歧义或损坏会停止，不会静默跳过。

## 手动安装

### Windows 10/11 x64（源码预览）

需要官方微信 4.x、CPython 3.12 x64 和可加载解码器的 VC++ 运行库。普通用户可以直接让
Codex 按本仓库 `AGENTS.md` 安装；不需要输入数据库路径，也不需要截图。

```powershell
.\scripts\codex_bootstrap.ps1 doctor
.\scripts\codex_bootstrap.ps1 install
```

初始化和日常对话方式与上文相同。Windows 状态由 DPAPI 和私有 ACL 保护；需要分别确认
初始化与快照保留。新微信构建、缺少本地数据或无法验证当前账号时停止，详见
[Windows 使用说明](docs/WINDOWS_SUPPORT.md)。

### macOS（保留原有安装与卸载流程）

需要 macOS 15 或更高版本、官方 Mac 微信 4.x、标准 CPython 3.9–3.13，以及带 Swift 的
Apple Command Line Tools。

```bash
./scripts/codex_bootstrap.sh doctor
./scripts/codex_bootstrap.sh install
```

安装完成后如果 Codex 没有立即显示新 Skill，请重启 Codex。安装器是幂等的：同一版本和
同一源码重复运行不会覆盖其他 Skill。已有同名但不属于本项目的 Skill 时会安全停止。

卸载对话层：

```bash
./scripts/codex_bootstrap.sh uninstall
```

卸载只移除本项目管理的 Skill 与 `current` 链接，保留运行环境、版本副本、密钥、快照、
任务和导出文件。任何私人数据删除都需要另行确认。

## 能导出什么

| 类型 | 当前能力 |
|---|---|
| 文字/系统消息 | 导出结构化 JSON、JSONL、Markdown 和 HTML |
| 图片 | V1/V2/旧 XOR 解密，WXGF 转 JPEG，选择最高可验证质量 |
| 语音 | 导出 SILK、逐条 M4A，或直接流式合并为 H.264 + AAC MP4 |
| 普通文件 | 仅导出消息元数据能够唯一验证的本机文件 |
| 表情 | 导出可唯一验证的本机明文资源；私有加密格式保留元数据 |
| 视频 | 当前仅导出消息元数据，不导出视频本体 |

微信本机没有保存的附件不能凭消息索引恢复。严格模式下，只要请求的媒体存在缺失、歧义、
损坏或不支持，整个导出就不会发布半成品。

## 实现原理

日常流程不是录屏，也不是逐条播放：

1. 用当前官方微信进程的只读证据绑定唯一账号；
2. 在旧的已验证快照中精确定位聊天；
3. Mac 协调本次内容需要的已初始化分片；Windows 刷新全部已初始化消息分片，避免跨分片遗漏；
4. 对 SQLite 主库、WAL 和 SHM 做锁定与一致性检查；
5. 仅重放已提交 WAL 帧并验证新快照；
6. 按聊天、绝对时间、消息类型生成不可变扫描计划；
7. 导出前再次校验计划摘要、数据库指纹、消息与媒体绑定；
8. 原子发布归档，失败时不留下伪成功目录。

纯语音 MP4 使用一次流式编码和一次完整解码探测，不再为每条语音反复生成、读取和删除
临时 M4A。完整可读归档仍保留逐条 M4A。

## 隐私和安全

- 本地导出 helper 没有遥测、远程 MCP 或上传接口。
- 默认导出不会把聊天正文写进命令行、日志或 Codex 对话。
- 如果用户主动要求 AI 总结聊天，选中的内容可能按照其 Codex 账号和数据设置进入模型处理
  链路；这与本地文件导出是两个不同动作。
- 普通导出客户端不接收数据库密钥、SQL、token 或 shell 指令。
- Mac 私有目录/文件使用 `0700`/`0600`；Windows 使用当前用户和 SYSTEM 专属 ACL，不用 chmod 假装私有。
- 项目没有键盘输入、粘贴、回车或微信发消息接口。
- 数据库直取不需要屏幕录制、辅助功能或麦克风权限。
- Full Disk Access 只能由用户在 macOS 系统设置中授予实际运行 Codex/Terminal 的宿主。

Mac 开发初始化会把验证后的数据库密钥存入当前用户私有文件；Windows 用当前用户 DPAPI 加密后保存。正式消费级版本仍需
完成签名、公证、Keychain 迁移和更多干净 Mac 兼容测试。

## 回归测试

安装普通运行依赖后执行：

```bash
./scripts/release_check.sh
```

它会运行：

- 公开仓库隐私/凭据/禁止文件扫描；
- Plugin/Skill 静态验证；
- direct、content、live 和 portable Python 测试；
- 隔离 HOME 中的安装、幂等与安全卸载测试；
- Swift release 构建、核心检查、媒体自检；
- 禁止键盘/粘贴/事件注入符号检查。

GitHub Actions 在 macOS runner 上执行同一套回归，并在 Windows runner 上验证原生 ACL、DPAPI、
SQLite 协调锁、合成加密快照和真实 SILK/FFmpeg。CI 不使用真实聊天，不能替代 Windows 微信实机验收。

## 当前边界

- Mac 保留现有本机路径；Windows 10/11 x64 是原生源码预览。Linux、WSL 和远程 Codex 云端不是本项目读取这台电脑微信的运行路径。
- 日常在线扫描保持微信打开；Mac 首次初始化可能要求正常退出微信，Windows 初始化保持微信打开，不采用 Mac 临时副本流程。
- Intel Mac 是目标支持架构，但需要更多实机回归。
- 当前仓库许可证状态为 `UNLICENSED`，不是正式开源发行；公开代码不等于商用或二次分发
  授权。项目所有者后续需要结合 GPL 运行依赖选择兼容许可证。
- 项目与腾讯、微信、OpenAI 均无官方隶属关系。
